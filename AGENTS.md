# auto-med — contexto para agentes (Codex, Antigravity, otros)

## Proyecto
Servicio para 1 usuario / 1 buzón de Outlook (Microsoft Graph, OAuth delegado). Sincroniza hilos por polling (delta queries), agrupa por `conversationId` en "tickets", hace OCR de PDFs escaneados (manuscrito incluido), y genera con un LLM una síntesis markdown acumulativa con plantilla editable. Zonas que el OCR no entiende se marcan con recuadro rojo para que el usuario las corrija (sobre todo desde el celular), lo que regenera la síntesis. Contenido sensible: producción con AWS Bedrock + Textract; pruebas con API keys. UI en español, mobile-first, lenguaje sencillo.

Plan completo: `/home/mani/.claude/plans/necesito-un-peque-o-software-swirling-taco.md` (7 fases). Estado: `docs/estado-del-proyecto.md`.

## Flujo de análisis (REGLA)
**El análisis es siempre bajo petición del usuario.** El sync de correo solo descarga y guarda correos y PDFs (RustFS); ningún hilo se rasteriza, pasa por OCR ni se envía a un LLM hasta que el usuario lo pide (`POST /api/threads/:id/analyze` o `POST /api/threads/analyze`). Estados de Thread: `sin_analizar` (defecto) -> `pendiente` -> `procesando` -> `listo | necesita_revision | error`. `seguimiento` (por hilo, opt-in) reanaliza solo al llegar mensajes nuevos a un hilo ya analizado; sin él se marca `tieneMensajesNuevos`. El barrido del pipeline solo recoge `pendiente`. Motivo: contenido sensible y muchos hilos antiguos cerrados.

## Síntesis incremental (REGLA)
Para reducir costo de LLM, un hilo ya analizado **nunca** se reenvía completo. Con síntesis previa utilizable, al LLM solo van: la síntesis markdown anterior, los mensajes NUEVOS (los que no están en `Synthesis.coveredMessageIds` de la última versión) con el OCR de SUS adjuntos nuevos, y la plantilla. Modo completo (`Synthesis.mode='full'`) solo sin síntesis previa utilizable o con `POST /api/threads/:id/synthesis/regenerate` (explícito, advierte mayor consumo). Cambiar la plantilla NO regenera: la actualización incremental sigue con el markdown y la plantilla anteriores y `GET /api/threads/:id/synthesis` expone `plantillaDesactualizada`. Corregir una región envía solo el documento afectado. Se respeta `SYNTH_MAX_INPUT_TOKENS` (novedades por tramos si no caben) y se guarda `inputTokensEstimados`/`mode` por versión. Los adjuntos ya procesados (sha256) no se vuelven a procesar ni a enviar a visión.

**OCR híbrido (REGLA):** `OcrService.process` primero extrae el texto de los PDFs con el extractor Node del propio proceso de la API (`PDF_TEXT_MODE=node|off`, `PDF_TEXT_MIN_CHARS`; ya no hay servicio Python/PyMuPDF). Las páginas `digital` se guardan con `text` = markdown, `engine='pdf-text'`, SIN regiones y sin llamar a `OcrEngine` ni a visión; las `escaneada` siguen el flujo OCR/regiones/visión. Se rasterizan todas (para `pagina_<k>.png`). Si el extractor está `off` o falla, todas pasan por OCR. Siguiente fase (no hecha): mejorar la estructura markdown de los escaneos.

## Stack
- Monorepo pnpm (`pnpm-workspace.yaml`): `apps/api` (NestJS + Prisma 7 + PostgreSQL), `apps/web` (Vite + React + TS + Tailwind 4 + react-router).
- Almacenamiento de PDFs/páginas: RustFS (S3 compatible) vía `@aws-sdk/client-s3`, path-style, módulo `storage`. Layout por hilo: `hilos/<threadId>/pdf_<n>/original.pdf` y `hilos/<threadId>/pdf_<n>/pagina_<k>.png` (helpers puros en `src/storage/storage-keys.ts`; n = siguiente índice libre del hilo; demo bajo `demo/hilos/...`). En BD solo `storageKey` (= clave del PDF; su carpeta es `dirname`) + `sha256`. Cada hilo guarda su propia copia del PDF y de las páginas; el OCR sigue deduplicado por sha256 (al reutilizarlo se COPIAN las imágenes con `StorageService.copy`; `OcrPage.imageKey` es el respaldo del visor). Lo guardado con el layout antiguo (`attachments/<sha>.pdf`, `pages/<sha>/<n>.png`) se migra con `pnpm --filter api storage:migrate` (`node dist/cli/storage-migrate.js`; simulación por defecto, `--apply`, `--delete-old`); los agentes no lo ejecutan contra la BD/RustFS reales.
- Interfaces intercambiables: `OcrEngine` (`local|textract`, se elige en la web) y `LlmProvider` (`bedrock|anthropic|openai|foundry|ollama`, se elige en la web; ollama = servidor local del usuario, URL editable en Ajustes -> IA; modelo recomendado por defecto `qwen3-vl:4b-instruct` (requiere Ollama >= 0.12.7; el tag `qwen3-vl:4b` es la variante de razonamiento) La app descarga el modelo sola al elegir Ollama y el asistente bloquea «Siguiente» hasta que esté listo.).
- docker-compose: SOLO desarrollo (hot reload; web con Vite en :5173, `web`, `api`, `ocr-local`, `rustfs` solo como comodidad de dev). **Producción = imagen única** (`Dockerfile` raíz + `deploy/entrypoint.sh`: SOLO web servida por la API vía `FRONTEND_BUILD_PATH`, api y OCR local PaddleOCR en 127.0.0.1:8000; RustFS NO va en el contenedor; solo expone :3000; volumen `/models`). `ocr-local` (OCR local en CPU, PaddleOCR; build en dos etapas, limpieza con `scripts/docker-clean.sh`) arranca siempre: la API usa `OCR_LOCAL_URL=http://ocr-local:8000` (fijado en el compose) y `GET /api/settings/ocr` informa el estado real del servicio (`entorno.servidor`, `servicioLocal`); en la web basta elegir «local». **Almacenamiento (REGLA):** se elige en la web (Ajustes -> Almacenamiento y asistente `/bienvenida`): instancia RustFS (endpoint, bucket, claves) o bucket de AWS S3 (región, bucket, claves opcionales/rol IAM); Setting `storage.config` (secreto cifrado AES-GCM, jamás devuelto), `StorageSettingsService` + `DynamicStorageService` (resuelve por llamada, sin reiniciar), `GET/PUT /api/settings/storage` y `POST .../test`; ya no hay `S3_*` en `.env` ni en el compose de producción; el compose de DESARROLLO sí fija `S3_*` apuntando al RustFS local (`S3_ENDPOINT=http://rustfs:9000`, `automed`, `rustfsadmin`) para que venga preconfigurado, y la config del panel `storage.config` sigue mandando (en producción no hay `S3_*`; el código aún los lee como respaldo no documentado y los usa el CLI `storage:migrate`); sin configurar la API arranca y `/api/health` da `storage:false`; cambiar de almacenamiento NO mueve los archivos ya guardados. **Ollama NO tiene contenedor (solo corre local):** lo pone el usuario en cualquier equipo y su URL se edita en la web (Ajustes -> IA), p. ej. `http://host.docker.internal:11434/v1` para el host (la API tiene `extra_hosts host.docker.internal`); en ese servidor `OLLAMA_HOST=0.0.0.0` y `OLLAMA_CONTEXT_LENGTH=8192`; la API autodetecta URLs candidatas en `GET /api/settings/ia/hardware` (`ollama.urlDetectada`, `ollama.motivo`) y la web guía si no hay conexión; `SYNTH_MAX_INPUT_TOKENS` <= `OLLAMA_CONTEXT_LENGTH` menos margen. Proveedores externos por API key (OpenAI, Anthropic, Foundry) y Bedrock/Textract con credenciales AWS. Servicios: rustfs, ocr-local (:8000), api (healthcheck `GET /api/health`), web. PostgreSQL es externo (`DATABASE_URL_DOCKER` desde el contenedor). Despliegue: `docs/despliegue.md`; benchmark OCR: `docs/benchmark-ocr.md`.
- **Config de Microsoft desde la web (REGLA):** el OAuth de Outlook (`clientId`, `tenantId`, secreto de cliente opcional cifrado AES-GCM y jamás devuelto por la API, `redirectUri`) se guarda en `Setting` `microsoft.config` y se edita en Ajustes (`GET/PUT /api/settings/microsoft`); precedencia panel > `MS_*` de `.env` (siguen valiendo como valores por defecto). La web sugiere la URL de redirección `<WEB_ORIGIN>/api/auth/callback`. Registro en Entra ID: `docs/entra-id-registro.md`.

## Convenciones
- Código y comentarios técnicos en inglés o español consistente; textos de UI siempre en español sencillo ("Listo", "Necesita tu ayuda").
- Botones táctiles ≥ 44px (clases `.btn`); diseño mobile-first.
- Iconos siempre de `react-icons`, familia Lucide (`react-icons/lu`, importados por familia); sin emojis ni símbolos Unicode como iconos. Decorativos con `aria-hidden`; icono solo en un botón lleva `aria-label`.
- Sin logs de contenido de correos/PDFs. Tokens cifrados AES-GCM (`TOKEN_ENC_KEY`).
- Seguridad (fase 7 + 8A): login de la app con **correo + contraseña** (argon2id, `@node-rs/argon2`) y JWT en cookies HttpOnly (`am_access` ~`JWT_ACCESS_TTL`=15m en `/`; `am_refresh` opaco, hash en BD, `JWT_REFRESH_TTL`=30d, solo en `/api/auth`, con rotación por familia y revocación ante reutilización). El primer usuario se crea por CLI o por `GET /auth/setup-status` + `POST /auth/setup`, que exige `SETUP_TOKEN`. Es independiente de Microsoft: Outlook se conecta después, ya con sesión (Ajustes -> Conectar Outlook: `POST /api/mail/connect` -> `GET /api/auth/callback` con state JWT firmado ligado al userId). Toda ruta de `/api` exige `SessionGuard` (JWT) salvo `auth/login`, `auth/refresh`, `auth/logout`, `auth/me` (solo informa), `auth/callback` (valida state + sesión) y `health`. `JWT_SECRET` (>=32 car.) es obligatorio: sin él la API no arranca. `SESSION_SECRET` y `ALLOWED_EMAIL` ya no existen. Login con rate limit (5/min por IP+correo, `@nestjs/throttler`); rutas mutantes validan `Origin` contra `WEB_ORIGIN` y exigen JSON. `configureApp` (`app.setup.ts`) aplica helmet, CORS solo a `WEB_ORIGIN`, límite JSON 256 kb. Cookies SameSite=Lax (+ Secure por `COOKIE_SECURE` o `MS_REDIRECT_URI` https). Usuarios por CLI: `pnpm --filter api user:create -- --email <correo> --nombre <nombre>` / `user:reset-password -- --email <correo>` (contraseña por prompt sin eco; en Docker: `docker compose exec api node dist/cli/user.js create --email ... --nombre ...`).
- Servicio OCR local: PaddleOCR exige `paddlex==3.0.3` y `langchain<0.3` (fijados en `requirements.txt`); si no carga cae a Tesseract y lo indica en `/health` (`fallback_reason`).
- Idempotencia por hash de contenido (no reprocesar hilos/PDFs sin cambios).
- Modelo de datos: `User → MailAccount (userId único, nulo en cuentas previas a la fase 8: la adopta `user:create`) → Thread → Message → Attachment → OcrPage → OcrRegion`, más `RefreshToken`, `Synthesis`, `Template`, `Setting`, `Report -> ReportRow`, `ThreadReportData` y `HospitalEvent` (`apps/api/prisma/schema.prisma`). `Template.kind` (`resumen`|`whatsapp`|`reporte`, registro `apps/api/src/templates/template-kinds.ts`): versión y plantilla activa por tipo; `resumen` = estructura de la síntesis (lógica incremental y `plantillaDesactualizada` usan solo este tipo), `whatsapp` = formato editable del mensaje de WhatsApp con el status del paciente (una llamada al LLM con SOLO la síntesis vigente; exige ticket analizado; se usa en cada petición, no regenera nada), `reporte` = columnas del Excel diario (lista `- Columna: instrucción`, parser `templates/report-columns.ts`). Endpoints `GET/PUT /api/templates/active`, `POST /api/templates/reset` y `POST /api/templates/preview` aceptan `kind` (`?kind=` o cuerpo; por defecto `resumen`, inválido -> 400).
- Reporte diario Excel (módulo `apps/api/src/reports`, job `generate_report`): censo de pacientes hospitalizados (cada hilo = un paciente; intermediario hospital-aseguradora) con columna de novedad; las altas salen una sola vez. Se genera a la hora configurada (`Setting` `reporte.programado|hora|zona`) o bajo demanda (`POST /api/reports`; reutiliza el que esté `generando`), se guarda en RustFS `reportes/AAAA-MM-DD/` y se descarga autenticado. **REGLA: el reporte NO dispara análisis** y nunca reenvía hilos al LLM: una llamada por hilo con SOLO la síntesis vigente + columnas, con caché `ThreadReportData` (hilo, síntesis, versión de columnas); **el reporte incluye SOLO hilos ya analizados** (con síntesis); los sin analizar no entran ni se listan (sin hoja de pendientes, sin `totales.sinAnalizar`, sin `GET /api/reports/pending`; la columna `Report.totalSinAnalizar` queda en desuso para no migrar) y los analizados con mensajes nuevos salen marcados 'Resumen desactualizado'. Datos de salud sensibles: sin contenido de correos/pacientes en logs; producción con Bedrock. Dependencia `exceljs`. **Bitácora de eventos («Añadir al Excel»)** (módulo `apps/api/src/events`, modelo `HospitalEvent`: único `(threadId, synthesisId)`, `fecha` 'YYYY-MM-DD' en `reporte.zona`): el usuario, en un ticket `listo`, pide un borrador (`POST /api/threads/:id/event-draft`: UNA llamada al LLM con SOLO la síntesis vigente + columnas de la plantilla `reporte` activa, y el evento previo del hilo si existe; NO guarda), lo revisa/edita y confirma (`POST /api/threads/:id/events`, valida hilo `listo`, síntesis vigente, claves ⊆ columnas, longitudes, fecha, estado; 409 si ya existe). `GET /api/threads/:id/events`, `DELETE /api/events/:id`. La hoja «Eventos» del Excel acumula los eventos de todos los hilos (fecha desc, columnas = vigentes + antiguas al final, fila resaltada si es de la fecha del reporte; «Resumen del día» suma «Eventos registrados: N (hoy: M)») sin llamar al LLM; el censo no cambia. Nunca se genera un borrador sin acción explícita del usuario; sin contenido de pacientes en logs.
